# AGENTS.md

Turkish-language LLM inference / fine-tuning VRAM & cost calculator. React 19 + Vite + Tailwind frontend served by one Express (TS) server; PostgreSQL-backed; generated from a Google AI Studio template. UI strings and user-facing API errors are Turkish.

Unfinished work is tracked in `PLAN.md` — the unified model-catalog plan is complete (all `hfId`s verified against the HF Hub), the Phase 2 landing page + SEO work is done, and the Phase 4 light brutalist redesign + wizard flow is complete (per the growth spec `docs/superpowers/specs/2026-08-25-public-tool-growth-design.md`).

## Commands
- `npm run dev` — runs everything: `server.ts` boots Vite in middleware mode, serving the SPA + API on http://localhost:3000. There is no separate frontend dev server.
- `npm run lint` — the only check: `tsc --noEmit`. No test framework exists.
- `npm run build` — vite build + esbuild bundle of `server.ts` → `dist/server.cjs` (`npm start` serves it in production mode).
- `npm run scrape:prices` — refresh GPU prices from RunPod/Lambda/Modal. Python, run via `uv` with the repo `.venv` (Python 3.13); needs `DATABASE_URL`.
- `npm run scrape:models` — refresh the unified model catalog into `hf_models` from Hugging Face **+ ModelScope + Ollama** (multi-provider, identity-deduped to one row per model with `sources` links + release dates); runs the same `refreshModels()` the admin endpoint calls (`tsx scripts/refresh-models.ts`); needs `DATABASE_URL`.
- `docker compose up -d --build` — production deploy (VPS): app (multi-stage `Dockerfile`) + `db` (postgres:16-alpine). The app publishes only to host loopback (`127.0.0.1:8081:3000`); TLS/reverse-proxy is handled by host-installed nginx (site `etc/nginx/sites-available/llminferencecalc.com.tr`, certbot). Needs `.env` with `POSTGRES_PASSWORD`; compose overrides `DATABASE_URL` to the internal `db` host with `?sslmode=disable`.

## Architecture
- Entry: `index.html` → `src/main.tsx` → `src/App.tsx` — a step **wizard** (`Wizard.tsx` + `WizardSummaryBar.tsx`) with a left scenario sidebar (`ScenarioSidebar.tsx`).
- Express API in `server.ts`: `/api/admin` (local admin login), `/api/gpu-prices`, `/api/models`. There is no user auth — the app is fully anonymous. (The Gemini-backed `/api/recommend-model` and `/api/advisor` endpoints were removed.)
- Data presets are the source of truth: `src/data/presets.ts` (incl. the `INFERENCE_ENGINES` engine-compat matrix: `details`, `supportedVendors`, `supportedQuants`, `vendorReason`/`quantReason`, and the MLX engine) + `src/data/modelCatalog.ts`; `src/data/gpuPresets.ts` holds GPU specs (incl. Apple Silicon M6/M5 Pro/M5 Max/M3 Ultra/M5 Ultra). Calculation logic in `src/utils/calculator.ts` and `src/utils/fineTuningCalculator.ts`. Engine/quant/vendor rules in `src/utils/engineCompatibility.ts`.
- Multi-provider model catalog: transformers config parsing is centralized in `src/server/modelConfig.ts` (HF **and** ModelScope share it; Dense/MoE active-params via a closed-form GQA/MoE formula — DeepSeek-V3 → ~37.6B active — plus multimodal detection/vision-params). Fetch clients: `hfClient.ts`, `modelScopeClient.ts` (token-free Hub API), `ollamaClient.ts` (HTML scraping — no official API, no architecture config). `modelRefresh.ts` dedupes to one row per real model (`canonical_id`), merges `sources`/`released_at`, hides duplicates by `linked`. Non-HF rows carry synthetic `hf_id` values (`ms:<id>`, `ollama:<name>`) — never assume `hfId` is a real HF repo; render links from `sources`. The model step shows a sticky `ModelDetailsPanel` (release date, provider links, architecture, multimodal) in a right column.
- DB schema is auto-created at boot (`runMigrations()` in `src/server/db.ts`, with retry in `server.ts initDb()`): tables gpu_prices, hf_models (legacy users/sessions/scenarios tables are dropped on boot). Have Postgres running with a `DATABASE_URL` like `.env.example`.
- Saved scenarios live in the browser's localStorage (`src/utils/scenarioStorage.ts`, key `llmcalc:scenarios`, with a change event for the sidebar). Custom models/GPU persist in `src/utils/customModelStorage.ts` (keys `llmcalc:customModels`, `llmcalc:customGpu`). Markdown export built by `src/utils/scenarioMarkdown.ts`.
- Live HF models are fetched by `useLiveModels` → `/api/models` and *replace* the static presets when non-empty (fallback to `MODEL_PRESETS` only when the API is down).
- Landing (`/`): server-rendered (`src/server/landing.ts`, light-brutalist, TR/EN) — hero + scenario cards + features + **methodology** + **data-sources/transparency** (prices scraped from RunPod/Lambda/Modal, no sponsorship) + model & GPU counts. The old "Calculator Modules" grid was removed.

## Gotchas
- The server keeps running if the DB is down (migration/seed failure is retried ~60s in `initDb()`), but DB-backed routes 500 — missing Postgres is the most likely cause of a broken dev run.
- Google sign-in was removed (KVKK): the only auth is the local admin login (`/api/admin/*`, needs `ADMIN_USERNAME`/`ADMIN_PASSWORD`, JWT cookie signed with `SESSION_SECRET`) reached via the secret route in `App.tsx`. The same admin session guards `POST /api/models/refresh` and `POST /api/gpu-prices/refresh` (`requireAdminSession`). Public users only ever GET cached rows — the results "live prices" panel has no refresh button. `SESSION_SECRET` unset generates a random per-boot key (sessions invalid on restart).
- Tensor parallelism / pipeline parallelism were removed (they never entered the math); `calculator.ts` uses a fixed 0.85 inter-GPU efficiency factor. Do not re-add a TP selector or the `tpEfficiencyPct` config field.
- Multimodal media tokens (item 2026-09-23): `calculator.ts` adds `images*imageTokensPerImage + audioSeconds*audioTokensPerSecond` to the input side (KV cache, prefill FLOPs, cost) **only** when the selected model `isMultimodal`. The conversion constants (defaults 1024 tok/image, 50 tok/s) are user-adjustable in the workload step; media inputs per persona live on `UserProfile`.
- Engine compatibility is enforced in the UI: engines incompatible with the selected quant are disabled (GGUF K-quants ⇒ llama.cpp/Ollama/MLX; FP16/FP8/AWQ/GPTQ ⇒ vLLM/TensorRT/SGLang/TGI), selecting an incompatible GPU vendor auto-switches the engine via `pickCompatibleEngine` (Apple → MLX), and presets/quant changes reconcile the engine too.
- The wizard step tabs intentionally show NO numbers; keep it that way (mode tabs and panel `▸ 01` indexes were removed).
- `db.ts` auto-enables SSL for any non-localhost `DATABASE_URL` host without `?sslmode=` — internal Docker/other plain Postgres hosts must append `?sslmode=disable`.
- Express runs with `trust proxy: true` (host nginx terminating TLS in front in prod); the admin login brute-force lockout relies on the real client IP.
- Keep `GPU_SLUG_PATTERNS` in `scripts/scraper/common.py` aligned with the GPU ids in `src/data/gpuPresets.ts` — scraped prices are matched to presets by slug.
- `vite.config.ts` disables HMR/file-watching when `DISABLE_HMR=true` (agent-editing mode); don't modify that block.
